# USDT 链上充值

用户像使用支付宝一样输入充值金额（元），选择 USDT 网络后，系统给出**唯一的应付 USDT 金额**和管理员配置的固定收款地址。用户转账后，后台监听链上入账，金额精确匹配就自动到账。

| `otok_usdt_bep20` | BNB Smart Chain | `0x55d398326f99059fF775485246999027B3197955` | **18** | 15 块 | `https://bsc-rpc.publicnode.com` |
| `otok_usdt_polygon` | Polygon PoS | `0xc2132D05D31c914a87C6611C10748AEb04B58e8F` | 6 | 64 块 | `https://polygon-bor-rpc.publicnode.com` |
| `otok_usdt_erc20` | Ethereum | `0xdAC17F958D2ee523a2206206994597C13D831ec7` | 6 | 12 块 | `https://ethereum-rpc.publicnode.com` |

- 合约地址、精度、chainId 都**写死在代码里**（`internal/pkg/otokchain/networks.go`），不能在后台修改，防止被配置成假币合约。
- EVM 链每次扫描前都会校验 `eth_chainId`，RPC 填错链会直接报错，不会误记账。

## 后台配置

1. 系统设置 → 支付设置 →「启用的服务商」里打开 **USDT 链上支付**。
2. 在服务商列表点「新建」，类型选 **USDT 链上收款**，然后勾选要开放的网络并填写配置：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 汇率（`exchangeRate`） | 是 | 1 USDT = X 元。由管理员手动维护，不会自动跟随行情 |
| 手续费率（`feeRate`） | 否 | 百分数，默认 0。USDT 渠道单独计费，**不受全局充值手续费影响** |
| 各网络收款地址 | 勾选的网络必填 | 填自己掌握私钥的钱包地址，**不要填交易所充值地址**（交易所可能不入账或合并入账）。EVM 地址大小写混合时会做 EIP-55 校验；零地址和 USDT 合约地址会被拒绝 |
| TronGrid API Key（`tronGridApiKey`） | 否，但强烈建议 | 到 [trongrid.io](https://www.trongrid.io/) 免费申请。不配置时公共额度很容易被限流，到账会变慢。该字段按敏感字段处理：列表接口不回显，审计日志脱敏 |
| BSC / Polygon / Ethereum RPC 地址 | 否 | 留空使用 PublicNode 公共节点，建议换成自己的节点。地址按明文保存，尽量不要用 URL 中带密钥的地址 |
| 订单有效期（`expireMinutes`） | 否 | 默认 30 分钟，范围 5～1440 |
| 过期后保留时间（`graceMinutes`） | 否 | 默认 60 分钟，范围 0～1440。订单过期后，这段时间内金额仍保留给该订单，到账仍会自动入账 |

约束：

- 同时只能启用**一个** USDT 服务商实例。
- 其他服务商（易支付等）不能声明 `otok_usdt_*` 类型。
- 存在待支付订单时，不能修改收款地址。
- 单笔最小 / 最大金额沿用渠道限额设置，按「元」计算。

## 金额规则

```
应付 USDT（基础） = ceil( 站内金额(元) × (1 + 手续费率/100) ÷ 汇率 , 2 位小数 )
实际应付         = 基础金额 + 识别尾差（0.00 ～ 0.99 中第一个空闲值）
```

- **站内金额**：
  - 余额充值：取实付基数，即折扣模式下的折后金额。
  - 订阅：取 `SUBSCRIPTION_USD_TO_CNY_RATE` 换算后的人民币价格。
- **到账余额**、赠金阶梯、余额倍率都沿用现有规则，与付款方式无关。
- **识别尾差**：
  - 同一收款地址上，同一时刻每个金额只分配给一张订单。
  - 依靠数据库部分唯一索引加 advisory lock 保证。
  - 尾差 100 个全部被占用时，下单返回「当前该金额下单人数较多」。
- 订单的 `pay_amount` 记录的是 USDT 金额，`currency` 为 `USD`。

## 到账流程

### 自动监听

- 后台服务 `OtokUSDTService` 每 15 秒执行一轮。
- 多实例部署时通过 Redis leader 锁保证只有一个实例在跑。
- 只扫描有待支付订单的地址，没有待支付订单时不发任何链上请求。

每一轮依次做这些事：

1. **释放金额预留**。满足以下任一条件就释放：
   - 已超过保留时间；
   - 订单已经入账；
   - 订单在付款前就 `FAILED`。
2. **扫描链上转账**：
   - TRON：调用 TronGrid `transactions/trc20` 接口（`only_confirmed`）。
   - EVM：调用 `eth_getLogs`，按 Transfer 事件和收款地址过滤，多个地址合并成一次请求。
   - 每次重扫最近「确认数 + 5」个区块，能发现链重组后的新位置。
3. **匹配订单**。必须同时满足：
   - 金额**精确相等**；
   - 区块时间落在「下单前 60 秒」到「保留截止时间」之间；
   - 订单状态是 `PENDING`、`EXPIRED` 或 `CANCELLED`。
4. **入账**：
   - 先在链上复核交易（receipt 状态、区块哈希、确认数）。
   - 再走上游的支付回调流程 `HandlePaymentNotification`。
   - 订单已过期超过上游 5 分钟宽限期时，会先刷新 `updated_at`，让订单回到宽限期内。
   - 失败的入账最多重试 5 次，间隔递增。

各类订单状态遇到匹配转账时的处理：

| 订单状态 | 处理 |
| --- | --- |
| `PENDING` | 正常入账 |
| `EXPIRED`（保留期内） | 入账，审计日志记 `ORDER_RECOVERED` |
| `CANCELLED`（用户取消后又转账） | 入账，审计日志记 `ORDER_RECOVERED` |
| `FAILED` 且没有付款记录 | 不匹配；转账留在「未匹配」，由管理员处理 |

### 用户提交 TxHash

付款页可以提交交易哈希加速确认。要求收款地址、合约、时间窗都对，交易没被其他订单占用，并且金额**精确等于**本单金额。

- 满足条件：立即绑定；确认数够了就入账，不够就等后台继续确认。
- 金额不符或超出时间窗：转账标记为「待审核」，用户需要联系客服。这样可以防止有人拿别人的转账来冒领。

### 管理员补单

后台「订单管理 → 查看」里，USDT 订单会显示「USDT 链上信息」，可以「手动补单」。

- 填交易哈希和原因；交易里有多笔转账时，还要填日志序号。
- 系统仍会做链上校验（收款地址、合约、确认数），但**允许金额不一致**。
- 审计日志记 `OTOK_USDT_ADMIN_BIND`。

### USDT 到账记录页

入口：后台「订单管理 → USDT 到账记录」。页面内容：

- **监听状态**：待支付订单数、未匹配、待审核、入账失败、等待确认，以及各条链最近一次成功扫描的时间和最近的错误。
- **转账列表**：可按状态、网络、交易哈希或地址筛选。
- **忽略**：未匹配或待审核的转账可以忽略，忽略后不再自动匹配。

## 环境变量

| 变量 | 说明 |
| --- | --- |
| `OTOK_USDT_WATCHER_DISABLED=1` | 关闭后台监听。只建议在排障时临时使用；关闭期间不会自动到账 |
| `OTOK_USDT_TRON_API_URL` | 覆盖 TronGrid 地址，可指向自建的 TronGrid 兼容网关，或联调用的模拟服务 |
| `OTOK_USDT_ALLOW_PRIVATE_RPC=1` | 允许 RPC / TronGrid 地址解析到内网 IP。默认开启 SSRF 防护，内网地址会被拒绝；自建内网节点或本地联调时才打开 |
| `OTOK_USDT_TESTNET=1` | 切到测试网：Nile、BSC Testnet（97）、Polygon Amoy（80002）、Sepolia（11155111）。**生产环境严禁开启** |
| `OTOK_USDT_TESTNET_<NET>_CONTRACT` | 测试网的 USDT 合约，`<NET>` 取 `BEP20` / `POLYGON` / `ERC20`；EVM 测试网必填 |
| `OTOK_USDT_TESTNET_<NET>_DECIMALS` | 测试网代币精度，可选 |

## 排障

- **用户说转了账但没到账**：
  1. 到「USDT 到账记录」用交易哈希或付款地址搜索。
  2. 搜不到：先看监听状态里对应网络的「最近错误」，常见原因是 RPC 限流或 TronGrid 没配 Key。
  3. 状态是「未匹配」：多半是金额不对，或者付款时订单金额已经被释放。核对后到对应订单里手动补单。
  4. 状态是「待审核」：用户提交的交易金额或时间不符，人工核实后补单或忽略。
- **从交易所提币**：多数交易所会从提币金额里扣手续费，到账金额就不等于应付金额。需要提醒用户按「到账金额」填写，或者让用户提交 TxHash 后人工处理。
- **查看日志**：日志关键字为 `[OtokUSDT]`，例如 `docker logs sub2api 2>&1 | grep OtokUSDT`。

## 已知限制

- **日限额统计偏低**：用户日限额和渠道日限额都按 `pay_amount` 累加，USDT 订单的数值只有人民币金额的约 1/7，会被低估。USDT 渠道不要配置日限额。
- **金额槽位有限**：每个基础金额最多 100 个尾差。保留时间越长，同时占用的槽位越多。
- **极晚到账可能串单**：保留期结束后金额会被释放，之后才到的转账可能匹配到使用同一金额的新订单，需要管理员核对后改绑。
- **刷新页面后看不到付款面板**：订单过期后刷新页面，付款面板不会再出现（这是上游恢复逻辑的限制），但保留期内到账仍会自动入账。
- **不支持原路退款**：需要链下人工处理。
- **汇率固定**：汇率由管理员手动维护，不会自动跟随行情。
